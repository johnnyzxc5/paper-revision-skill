# Adapt the workflow to a paper

Use for a new paper or a change of project. Reuse inspected project notes rather
than creating a second configuration system. Establish the following from the
author's request and available artifacts; ask only for missing decisions that
materially affect the work:

- Scientific question, proposed contribution and target reader.
- Evidence available: proof/derivation, simulation, measurement, observations or
  literature synthesis. A paper may combine these without transferring the
  evidential strength of one to the others.
- Manuscript/bibliography/data locations, applicable project profile and venue.
  Apply IEEE-specific rules only for an IEEE target or an explicit author choice.
- Current task and stage, accepted text, planned additions, deferred sections and
  the trigger for returning to them. A section can contain completed subsections
  while awaiting additional ones. Approximate completion percentages supplied by
  the author are scheduling context, not measured scientific validity.
- Configured evidence sources and notebook IDs/aliases by role, if consultation
  is required. Preserve the route and exact-draft approval workflow.

Start a new paper from its supported answer and argument, choosing the theory,
empirical or mixed architecture in [drafting-playbook.md](drafting-playbook.md).
Do not assume a robot, Hamiltonian model, neural network, fixed section numbering,
experiment count, reviewer roster or bibliography from a previous project.
Profiles specialize the common workflow; they do not establish scientific facts.

## Source roles and project isolation

The reusable roles are project context, technical/domain evidence and writing
guidance. `theory` means the relevant domain's technical sources, not necessarily
control theory. Each project binds its own notebooks, source policy, and library;
do not silently consult an unrelated existing notebook to fill a missing role.

If consultation is optional and local evidence suffices, proceed locally. If a
required role has no configured source/service, mark the affected consultation
blocked while continuing independent work. The existing receipt guards still
apply to any claimed NotebookLM consultation. For a configured writing library,
use its inspected source registry. The bundled registry is an illustrative example;
customize its titles and profiles rather than treating it as a required library.

## Stage-aware scope

Read completed text when needed for definitions and dependencies, without
restyling it automatically. Record a newly observed contradiction as a bounded
finding and surface any required scope change through the existing route gate.
Do not equate an intentional deferral with oversight or claim the whole paper is
finished because an in-scope block is complete. Abstract, introduction and
conclusion reconciliation can be scheduled for synthesis/submission, after the
body stabilizes, when that is the author's chosen order.

## Retain learning without overfitting

Keep project decisions and [claim history](claim-history.md) with that paper.
Promote only the transferable reasoning into shared guidance. Each proposed
generalization must identify its source, applicability and exceptions; an author's
preferred realization is not a universally necessary design. Use synthetic examples
or author-approved cases with a stated evidence boundary. Future skill changes require
an explicit update task; using a skill does not automatically rewrite it.
